# Приёмка четырёхлистового обработчика

Исторический отчёт версии **1.3**. После новой обратной связи заказчика действующий
контракт — **1.4**, пять листов и строгий допуск в «Данные»; актуальная приёмка в QA_REPORT.md.

Проверено 2026-10-08 на Windows, Python 3.14.5, openpyxl 3.1.5.
Реализован запуск для настоящего XLSX: `normalize.py` создаёт один новый файл с листами
**Данные, Проблемы, Оригинал, Аудит** именно в таком порядке. `restore.py` восстанавливает
побайтно исходную книгу из аудита. Команды установки и запуска приведены в [README](../README.md).

Контракт — [SPECIFICATION.md](SPECIFICATION.md) **1.3**; план до реализации —
[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md). Ответ заказчика DEC-21 фиксирует
безусловную диагностику префиксов 00/810, включая десятизначный `0000000000` и
одиннадцатизначный `81012345678`. Каталог содержит 169 независимых эталонов.
Проверки операторских диапазонов и обращения к сторонним сайтам не выполняются.

## Реализация

`normalizer/reader.py` проверяет ZIP/CRC/XML и схему, выбирает лист и получает фактические
строки из XML вместо доверия `dimension`. Типы, исходная числовая запись, формулы,
метаданные, гиперссылки и XML ячеек сохраняются. Даты Excel анализируются до потери
исходного serial при автоматическом преобразовании библиотекой. Выбор листа и
перестановка четырёх колонок поддерживаются.

Анализаторы `phone.py`, `dates.py`, `names.py` работают по контракту независимо от
исследовательских прототипов и каталога ожиданий. Однозначные значения стандартизируются;
неопределённые остаются исходными с кодами проблем. Контекст телефона сохраняется в аудите
и проблемах при успешном извлечении основного номера. Из datetime извлекается написанный
календарный день; время и offset сохраняются. Латинские имена остаются для проверки,
NFC применяется согласно спецификации.

`deduplicate.py` оставляет первую физическую строку на канонический телефон без заполнения
её полей из других записей. Разные имена или даты помечают всю группу; различие источников
записывается в аудит. Неопределённые телефоны не объединяются. Проблемные дубли присутствуют
в «Проблемах», все исходные записи — в «Оригинале».

`report.py` записывает четыре листа. Полный входной XLSX включается в аудит частями Base64;
длинные JSON также делятся на части с индексами и хешами. Формулы сохраняются строками без
исполнения. Большие числа сохраняются без округления представления. Превышение пределов
Excel приводит к отказу без усечения значения.

`invariants.py` до публикации перечитывает результат, проверяет схему, строки, представителей,
проблемы, изменения и точное восстановление байтов исходника. `files.py` публикует только
новый файл. Повторный запуск и появление назначения во время обработки не затирают файл;
проверяется и неизменность входа. Собственные временные файлы убираются при отказе.

## Результаты проверок

Команда `python -m unittest discover -s tests -v`: **28/28** тестов — 10 генератора,
4 анализаторов и 14 конвейера. Один тест анализаторов перебирает все **169 эталонов**,
сравнивая значение, каноническое представление, статус и коды проблем. Ожидания не
рассчитываются проверяемым анализатором. Сквозной тест использует все **14 XLSX** suite,
включая корректные книги, обе системы дат и ожидаемые технические отказы.

Проверены:

- Примеры заказчика, добавочные и заметки телефона, разные форматы существующих дат,
  все формы словаря месяцев, ISO datetime без секунд и границы дробного Excel serial.
- Первый дубль с неполными полями, конфликты всей группы, отсутствие ложного конфликта NFC,
  сохранение латинского имени и пригодность телефона с контекстом для дедупликации.
- Пустые и скрытые строки, перестановка колонок, явный выбор листа, неправильный `dimension`,
  нестандартное имя XML-части листа, rich text и дополнительные листы исходной книги.
- Гиперссылка только как метаданные, формулы и ошибки, bool, serial 60, точное большое число,
  длинные metadata/value JSON и отказ при значении длиннее допустимого для Excel.
- Ошибки CRC, повторяющиеся ZIP-части и XML-строки, сбой сохранения, коды CLI,
  существующее назначение, повреждение аудита, два одновременных процесса настоящего CLI.

В гонке публикации один CLI завершился успешно, второй получил отказ; результат восстановил
исходник точно. На Windows проверены и очистка временного файла, и отсутствие перезаписи.

Исследовательские стенды повторно запущены на снимке спецификации 1.3:

## Границы приёмки

Настоящий файл заказчика не предоставлен: примеры выше получены из генератора.
Для своего файла нужно выполнить команду в начале README. Наличие проблемных строк
совместимо с успешным завершением: они сохраняются с причинами в отдельном листе.

Технические пределы и отказ без публикации определены спецификацией и CLI. Зашифрованные
книги, XLS/XLSM, DTD/ENTITY и повреждённые контейнеры не принимаются. Лимит строк исходника
не гарантирует вместимость аудита: его строки тоже ограничены пределом Excel.
Поведение публикации на POSIX реализовано, но гонка на этой платформе не испытана.
Исторические отчёты исследований сохранены и описывают свой этап; готовый обработчик
проверен отдельными приёмочными тестами, перечисленными здесь.
