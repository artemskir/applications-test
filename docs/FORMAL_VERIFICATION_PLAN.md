# Следующая фаза: независимая модель и проверяемые утверждения

Для спецификации 1.7 план расширен GROUP_RECONCILIATION_PLAN.md: проекция личного
имени, явные доноры группы, допуск подтверждённой версии при конфликте, дополнительный
перебор 6175 последовательностей дат и повреждение GROUP_RESOLUTION. Ниже — исходный
план фазы 1.6, сохранённый для прослеживаемости.

Зафиксирован до реализации, 2026-10-08. Baseline: коммит f1a1bde, спецификация 1.5,
пять листов, 44 основных и 13 расширенных тестов. Материалы заказчика с упоминанием
1.4 оцениваются относительно фактической 1.5. Бизнес-политика без согласования не меняется.

Цель — проверить конкретные математические утверждения на явной области, а не
объявить корректность всех имён, телефонов и XLSX на основании числа тестов.

1. Аудит name_roles и run_qa. Ручные исключения DEC-25 — согласованная политика;
   отдельно измерить скрытые словарные роли и пропуски. SHA/счётчики — целостность,
   а не точность. Составные/длинные ФИО вне грамматики остаются UNKNOWN/REVIEW.
2. Независимая модель без импортов production. Телефоны ограниченного алфавита,
   календарь, свидетельства ролей и допустимые назначения; политика DMY/исключений
   применяется перед подсчётом разрешённых интерпретаций. |C(x)|=1 относится к
   контракту, не к единственной возможной интерпретации в реальном мире.
3. Все 48 абстрактных строк: 4 телефона × 3 имени × 2 даты × 2 источника.
   Перебрать все упорядоченные последовательности длины 1, 2, 3 и пустую:
   1 + 48 + 2304 + 110592 = 112945. Сравнить реальную дедупликацию с независимым
   результатом: первая строка, конфликты, admitted, выходной порядок, точный учёт.
   Разделить доказательство для абстрактных FieldResult и проверку связи с анализаторами.
4. Hypothesis RuleBasedStateMachine: операции добавления/удаления/изменения/перестановки
   и инварианты после каждого шага. Проверить независимость несвязанных групп.
5. Независимый инвентарь из ZIP/XML (не production reader): физические координаты,
   типы, raw значения, формулы, стили/epoch/ссылки, хеш сериализации. Повторно читать
   результат; проверять все идентификаторы, содержимое, изменения, ссылки и точные байты.
6. Явный P0-реестр и фактически выполненные IDs. Пропуск/нехватка теста/авария CLI/
   timeout — провал, а не зелёный итог. Инструментировать subprocess coverage и
   проверить на дочернем процессе, где родитель не импортирует обработчик.
7. Подменять только изолированную копию/память: порядок дат, последний дубль,
   пропуск ROW, частичный телефон, отсутствие календаря, изменение Оригинала.
   Независимая проверка обязана обнаружить каждый дефект, включая подмену row_id.
8. Оценить CrossHair для чистых функций; сохранить контрпример к намеренно неверному
   контракту и статус анализа корректного. Отсутствие контрпримера не полное доказательство.
   Для маленькой модели полный перебор сильнее covering array. Для расширенных факторов
   отдельно измерить покрытие всех пар/троек, не приравнивать branch coverage к MC/DC.
9. Независимые размеченные авторские примеры ролей из третьего проекта плюс сравнение
   всех исходных ролей в локальных справочниках. Не использовать production-ответ
   для эталона и не объявлять словарные данные независимым holdout. Реальные роли
   контекстны; пересечения и отказы требуют отдельного отчёта.

Ответ заказчика зафиксирован в DEC-29 спецификации 1.6: для «Иван Иванов Петрович»
извлечь подтверждённое имя, остальные компоненты направить на проверку. Роль
«Петрович» не угадывается; NAME_AMBIGUOUS исключает заявку из «Данных».

Результат: формальная спецификация области, reference model, воспроизводимые стенды,
контрпримеры/регрессии, матрица FM-01…12, покрытие условий, аудит QA и отчёт P0.
Все результаты — новые каталоги. Исторические доказательства не переписываются.
