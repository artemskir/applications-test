# Согласование заявок, спецификация 1.7

Решения DEC-30–34 согласованы до изменения реализации. Основание — примеры
заказчика и полностью прочитанный research/deep-research-report_2.md.

1. Устранить ранний отказ по пересечению словарных ролей. Для 2–3 слов перечислить
   все допустимые назначения, требовать одно положение FIRST_NAME во всех них.
   FIRST допускается только при подтверждении НЭН+russiannames или проверенным
   исключением. Остальные роли остаются множествами; неизвестные слова не угадывать.
   Одиночные неоднозначные слова и специальное правило Петрович не расширять.
2. На краях слов/поля удалить только U+200B/U+FEFF в рабочей копии; сохранить
   позиции и исходный текст в действии NAME_INVISIBLES_REMOVED. Внутренний знак
   между буквами не удалять. Пробелы NBSP/NNBSP нормализовать прежним правилом.
3. Сохранить исходные FieldResult каждой строки. Выделить отдельные data_fields
   представителя: для Имя/Телефон/Дата — первый canonical без кодов в группе,
   для Источник — буквальное значение первой строки. При отсутствии подтверждения
   оставить прежний проблемный результат, исключить итог из Данных.
4. Сравнивать подтверждённые ФИО независимо от порядка компонентов и е/ё, только
   внутри одного телефонного ключа. Совпадение первого имени обязательно; наборы
   остальных компонентов должны совпадать или один дополнять другой (подмножество).
   Если хотя бы одна пара подтверждённых значений несовместима, конфликт относится
   ко всей группе. Пропуск/битое поле сами по себе не являются конфликтом двух
   подтверждённых значений. Инициалы остаются исходной проблемой: не расшифровывать
   их, а брать известное полное имя из другой строки того же телефона (DEC-31).
5. GROUP_RESOLUTION хранит выбор всех четырёх полей, row_id и ячейку донора,
   каноническое и отображаемое значение, правило выбора, допуск и конфликты.
   Отдельный FIELD_CHANGE описывает только нормализацию исходной строки. Проверять
   обе цепочки до публикации, включая доноров и отсутствие скрытой подмены поля.
6. В Данных не более одной строки на canonical_phone. Ошибки исходных строк и
   конфликты сохраняются в Проблемах/Проверить даже при наличии чистого итога.
   GROUP_RESOLUTION не заменяет ROW, Original или встроенный исходный XLSX.
7. Обновить независимую модель 48 состояний и полностью проверить 112945
   последовательностей длиной 0–3; сравнивать также значения и доноров итоговых
   полей. Добавить реальные CLI/XLSX регрессии всех примеров и отрицательные
   случаи; проверить восстановление, изоляцию групп и повреждение нового аудита.

Исследование предлагает тот же независимый эталон и проверку сохранности, которые
уже реализованы в 1.6. Его утверждения о версии 1.4, родительском coverage и запрете
дополнения устарели. Новый запрет на незаметное объединение исполнен явной цепочкой
доноров; дополнение разрешено заказчиком. Ресурсы и runtime-зависимости остаются
локальными и закреплёнными. Цели coverage/MC/DC не подменяют проверку контракта.

Математическая область проверки конечна: доказательство по 48 абстрактным состояниям
проверяет выбор и сохранность, но не гарантирует классификацию всех человеческих имён.
Год 2062 не исправляется; serial без подтверждающего формата не превращается в дату.

После проверки всех трёх исходных словарей и примера фамилии Ivan заказчик утвердил
DEC-35: любой исходный словарный overlap у одиночного слова требует проверки;
ручные исключения не перекрывают эту проверку. Для ФИО контекст сохраняет прежние
подтверждённые исключения. Чистый генератор должен выбирать имена из полного
пересечения НЭН+russiannames без LAST/PATRONYMIC, а не из пяти примеров пользователя.
Из-за DEC-35 имя, выделенное из ФИО, может потребовать проверки при повторном чтении
лишь Данных; нельзя обещать идемпотентность проекции без сохранённых свидетельств.
