# Локальные корпуса и проверка нормализатора 1.5

Дата: 2026-10-08. План до исправлений — [RESOURCE_QA_PLAN.md](RESOURCE_QA_PLAN.md).
Спецификация 1.5, программа 1.2.0. Результаты других агентов проверены собственными
эталонами; их каталоги не изменялись. Обработка остаётся локальной, с пятью листами.

## Проверка выводов OpenCode и Grok

| Случай | Что установлено и сделано |
|---|---|
| `；７９１７４００５２１９` | Не иностранный телефонный префикс. Целый номер извлекается с PHONE_EXTRA_CONTEXT; исходная пунктуация сохраняется. Уже в 1.4 строка уходила в Проблемы, не в чистые Данные. Ожидание PHONE_UNSUPPORTED_PREFIX ошибочно. |
| `89174📞005219` | Номер уже отклонялся, но суффикс `005219` ошибочно получал диагноз неподдерживаемого префикса. Теперь PHONE_INVALID; никакого склеивания. |
| `📞89174005219` / `89174005219📞` | Однозначный целый кандидат и внешний контекст: canonical + PHONE_EXTRA_CONTEXT, Проблемы/Аудит. Эмодзи внутри цифр либо несколько номеров запрещают извлечение. |
| Акут, variation selector, keycap у цифр | Согласованное уточнение DEC-27: изменённая цифровая запись → PHONE_INVALID, raw сохраняется. Эти символы относятся к Unicode marks, а не все к управляющим Cc. |
| `09 03 2026` | Не входило в прежнюю грамматику: «пробелы вокруг разделителя» не означает «пробел вместо разделителя». Заказчик согласовал DEC-28; теперь 2026-03-09. Сохраняется прежний DMY и однозначный MDY при невозможном DMY. |
| `09 / 03 / 2026; 25 / 09 / 2026` | Исправлен диагноз: DATE_MULTIPLE, ранее DATE_UNSUPPORTED. Ни раньше, ни сейчас дата не выбирается произвольно. |
| `доб. 917-400-52-20` после основного номера | Исправлено ложное принятие второго телефона за диапазон добавочных. Разные номера → PHONE_MULTIPLE, поле не получает canonical/ключ дубля. |
| Пустой/буквенный хвост `доб.`, `#abc`, `вн. офис` | Исправлено ложное успешное извлечение: повреждённый помеченный добавочный → PHONE_INVALID. Обычный внешний текст без маркера продолжает обрабатываться по спецификации. |
| `доб. 00-12-34-56-78` / `доб. 810-123-45-678` | Следующая итерация нашла скрытый обход запрета префикса. Хвост с 10/11 цифрами нельзя маскировать как диапазон добавочных: PHONE_UNSUPPORTED_PREFIX. |
| `2026-09`, `2026/09` | Исправлен диагноз неполной даты: DATE_INCOMPLETE. День не дополняется. |
| Serial 46271 с `h:mmmm d yyyy`, `d yyyy mmmm:ss` | Исправлен ложный отказ. `mmm`…`mmmmm` — месяц; только `m`/`mm` рядом с часами/секундами могут быть минутами. Настоящие форматы без месяца остаются DATE_INCOMPLETE. |
| Grok: повтор основного номера после `доб.` | Само совпадение полного номера не является новым человеком: одинаковые кандидаты допускаются по §6.2.8. Сохраняется контекст; это исправление ожидания, не ошибка приложения. |
| Grok: фамилия + отчество без имени | Уже направляется на проверку с NAME_AMBIGUOUS. Отличие ожидаемого кода NAME_NOT_FIRST не является приёмом такой строки в Данные. Консервативная классификация не менялась. |
| OpenCode: `restore_bytes()` якобы теряет байты | В `test_integrity_edge.py` сравнивается весь `(bytes, metadata)` с `bytes`; длина 2 — длина кортежа. Правильная проверка `restore_bytes(output)[0] == input_bytes` проходит. |
| OpenCode: шифрование только в локальном ZIP-заголовке | Подтверждён пропуск предварительной проверки: центральный каталог сообщал другое. Теперь объявление шифрования в любом из двух заголовков даёт INPUT_INVALID. Проверены локальный, центральный и оба флага. |
| OpenCode: DTD якобы принимается | Мутация искала отсутствующую XML-декларацию и фактически не вставляла DTD. Реальная DTD/ENTITY-фикстура в собственном стенде отклоняется без публикации. |

Различение месяца и минут сверено с [официальными правилами Excel](https://support.microsoft.com/en-us/excel/review-guidelines-for-customizing-a-number-format).
NFC и категории сверены с [UnicodeData 16.0.0](https://www.unicode.org/Public/16.0.0/ucd/UnicodeData.txt)
и [NormalizationTest](https://www.unicode.org/Public/16.0.0/ucd/NormalizationTest.txt).

## Выбор источников и архитектуры

Рабочий CLI использует только openpyxl/et-xmlfile и включённый проверяемый справочник
имён. Новых рабочих зависимостей нет. Публичные корпуса подключены к отдельному QA,
а не к решению о допустимости заявки. Это сохраняет согласованную структурную проверку
телефона и предотвращает расширение датовой грамматики сторонним эвристическим парсером.

| Источник | Как используется локально | Ограничение |
|---|---|---|
| Unicode 16.0.0: UnicodeData, NormalizationTest, confusables | Все Nd/marks, непробельные Cf/Cc, NFC, визуальные двойники цифр | NFKC и «похожие» буквы не превращаются в цифры; версия UCD проверяется |
| [CLDR 47](https://github.com/unicode-org/cldr-json/tree/16f6b8578ba5fe98959034706f337674f816fc3f) | Русские/английские формы месяцев | Узкие односимвольные формы и неутверждённые сокращения остаются проблемой |
| [libphonenumber 9.0.41](https://github.com/google/libphonenumber/tree/b68df884d42d5e9860fc1956a99ce6afae361100) | Примеры RU/KZ и шесть группировок цифр, включая короткие/длинные неподдерживаемые формы | Нет проверки оператора, страны или существования номера |
| Локальные russiannames + НЭН и размеченные примеры | Сохранность имени, NFC, повторная оценка классификации | Sorokin и russiannames не независимы; словарь не доказывает реальную роль слова |
| Hypothesis / AllPairs | Мутации из закреплённых классов и реальные комбинации XLSX | Seed/пары не доказывают полноту произвольных входов |

Закреплены девять файлов, commit/version, размер, SHA-256 и лицензии Unicode-3.0 /
Apache-2.0 в [resource_sources.lock.json](../research/resource_sources.lock.json).
Отдельная команда загрузки проверила HTTP 200 и все хеши. QA только читает кеш:
изменённый или отсутствующий файл вызывает отказ без обращения к сети. Два постоянных
теста проверяют именно эту границу. Минимальные QA-зависимости вынесены в
`research/local-qa-requirements.txt`; DuckDB и исследовательские парсеры не требуются.

## Эксперименты и фактические результаты

Baseline: 36 основных тестов проходили. Из первых 32 новых минимальных примеров
совпали 13; остальные различались из-за подтверждённых дефектов или новых согласованных
правил. Протокол до изменений: `generated/resource-baseline/cases.json`.
Обходы 00/810 отдельно воспроизведены из исходного кода коммита `3aa8b23`:
`generated/resource-baseline/prefix-cases.json`. Всего исправлены восемь классов дефектов;
расширение пробельных дат и строгая граница marks учитываются отдельно как решения.

При создании ресурсного стенда исправлены ошибки самого стенда: ожидание полностью
пустой хвостовой строки вне установленного диапазона, не применявшаяся из-за XML
namespace мутация, затем ошибка байтовой regex-замены. Неуспешные прогоны сохранены в
`generated/resource-qa-first/` и `resource-qa-second/`; они не являются приёмкой.
Первый исправленный корпус прошёл в `resource-qa-third/`, после расширения — в
`resource-qa-1.5-acceptance/`. После находки обходов префикса выполнен новый полный прогон.

Финальная приёмка: `generated/qa-1.5-published/`, seed **20261010**, максимум 1000 примеров
на свойство: **44/44** основных + **13/13** расширенных тестов, без пропусков.
Пять больших семейств Hypothesis дали по 1000 вызовов; конечные стратегии — меньше;
30 последовательностей операций. Существующие комбинации покрыли **114 пар** и восемь
опасных троек. Девять целевых мутаций обнаружены: `generated/qa-1.5-verified-mutations/`.

Финальный ресурсный прогон: `generated/resource-qa-1.5-verified/`, seed **20261010**,
лимит 300, **112 944 проверяемых условия, 0 нарушений**. Это число assertions,
включая сохранность raw, а не число разных заявок. Покрытые классы:

- 34 постоянных минимальных примера; каталог генератора **215 сценариев**, 14 XLSX.
- Все **760 Nd**, **76 цифровых блоков**, **1 151 Nl/No**, **2 501 marks** и
  **225 непробельных Cf/Cc**. Marks вставлялись во все 13 позиции телефона и в дату.
- **19 965** официальных NFC-векторов, 62 кириллических проверки ключа имени,
  37 визуальных двойников цифр без разрешённой цифровой семантики.
- 58 утверждённых и 24 неподдерживаемых формы CLDR; **2 400** календарных комбинаций,
  включая високосные столетия, крайние годы и пробельные даты.
- 11 примеров RU/KZ в двух формах; **1 800 уникальных генераций** шести метаданных
  группировки; **300 уникальных комбинаций** Unicode-цифр, номера и повреждающего знака.
- **28 запусков настоящего CLI**: 17 результатов с пятью листами и 11
  контролируемых отказов без публикации. Inline/shared/rich text, UTF-16, UTF-8 BOM,
  ложный dimension, некорректные UTF-8/кодировка/сущность, оборванный XML, отсутствующий
  лист, повтор ячейки, плохой shared-string index, DTD/ENTITY, флаги шифрования
  локального/центрального заголовка и лимит распаковки.
- 11 комбинированных книг покрыли все **67 пар** пяти ресурсных факторов.
  Rich/shared записывают A2 в NFC; NFD при этом остаётся в дубликате A3.

В каждом из 17 результатов независимо проверены все исходные четыре поля, идентификаторы
строк, ROW-аудит, понятный лист Проверить, чистые Данные, отсутствие активных формул
и восстановление всего файла побайтно. Исходники остались неизменными. Проверены SHA
**45 XLSX-артефактов**. Строгие ожидания не дали ложных принятий/отказов, потери данных,
crash/timeout; неизвестные имена не считаются доказанно недействительными.

Покрытие полного P0/генеративного прогона: **1011/1103** statements (**91,66%**),
**432/508** branches (**85,04%**). Это coverage родительского процесса;
дочерние CLI и самостоятельный ресурсный стенд в эти проценты не входят.
Машинные счётчики и хеши: [RESOURCE_QA_EVIDENCE.json](RESOURCE_QA_EVIDENCE.json).

Грязная книга из 215 строк обработана CLI: **55 Данные, 160 Проблемы**, 29 дублей,
215 исходных строк. Восстановление через CLI совпало с входом побайтно:
[dirty_result.xlsx](../generated/normalizer-1.5-final/dirty_result.xlsx).

## Оставшиеся ограничения

Классификация имён на прежних 41 размеченных примерах — **35/41** совпадений;
это набор разработки, не независимая оценка точности. Неизвестные редкие/нерусские
имена направляются на проверку. Политика ролей в этой итерации не расширялась.
Цифровой формат телефона не доказывает реальность контакта.

Полный Unicode Normalization Test используется для проверки NFC среды; это не
обещание принять каждый его символ как имя. Pairwise не покрывает все сочетания,
контролируемый маленький лимит распаковки не является измерением памяти при ZIP bomb.
Проверенная платформа — Windows/Python 3.14.5/UCD 16.0.0; POSIX не испытан.
Согласованные вопросы закрыты DEC-27/28; гарантия остаётся ограниченной перечисленными
грамматиками и проверенной сохранностью, а не любым произвольным содержимым XLSX.

Команды подготовки, запуска и проверки протоколов — в [README.md](../README.md).
