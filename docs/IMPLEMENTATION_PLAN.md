# План реализации четырёхлистового обработчика

Это исторический план первого обработчика. Текущий результат имеет пять листов,
спецификация 1.7; актуальная итерация — GROUP_RECONCILIATION_PLAN.md.

План зафиксирован до кода обработчика. Бизнес-контракт — SPECIFICATION.md 1.2;
правила DEC-01…20 и независимый каталог 167 сценариев на старте не меняются.
Последующее уточнение заказчика DEC-21 записано в версии 1.3 до финальной проверки:
00/810 безусловно отклоняются; добавлены два эталона, итоговый каталог — 169 сценариев.

1. Создать отдельный пакет normalizer и CLI normalize.py / restore.py.
2. Снять неизменяемые байты входа; проверить ZIP (имена, CRC, XML, обязательные
   отношения OOXML). Разбирать локальные части, не обращаться к адресам отношений.
   Поддержать выбор листа, переставленные колонки, внутренние пустые строки;
   фактический диапазон получать из XML, а не dimension. Объединения отклонять.
3. Сохранять типы, исходный XML, стили и гиперссылки. Numeric serial сохранять
   до преобразования openpyxl; формулы не вычислять. Rich text читать как текст,
   исходные runs сохранять в XML/встроенной книге.
4. Реализовать независимые анализаторы телефона, даты, имени, источника.
   Сначала проверить их на утверждённых ожидаемых значениях и кодах; не получать
   ожидания вызовом этих же анализаторов.
5. Дедуплицировать после анализа всех полей, отметить конфликты всей группы.
6. Записать ровно Данные, Проблемы, Оригинал, Аудит. JSON и байты делить на части
   по 30 000 символов; не укорачивать бизнес-значения. Проверить восстановление
   исходника, инвентаризацию строк и связь с представителями до публикации.
7. Публиковать новый файл без замены существующего; на Windows rename, на POSIX
   link временного файла с последующим удалением собственной временной ссылки.
   Восстановление использует ту же защиту и проверяет Base64, индексы, размер, SHA.
8. Выполнить каталог, сквозные дубли, CLI, ошибки контейнера/схемы, metadata,
   сохранность и гонку назначения. Показать реально созданный четырёхлистовый XLSX.
   В README поставить готовую команду для своего файла первой.

Технические ограничения фиксируются заранее и доступны через CLI:
`--max-input-bytes` = 104857600, `--max-uncompressed-bytes` = 536870912,
`--max-rows` = 1048575. Превышение — exit 5, без результата. Число ZIP-частей
не более 10000; XML DTD/ENTITY не принимаются. Итоговые пределы Excel обязательны
независимо от этих настроек. Ограничения не считаются ошибками отдельных строк.

Различать выход 0 с проблемами данных и технические отказы 2/3/4/5. Не сохранять
строковые ошибки вместо аварии программного кода. Все операции с реальными файлами
входа — только чтение; тестовые файлы и результаты создаются в новых путях.
