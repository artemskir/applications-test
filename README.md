# Очистка заявок XLSX с сохранением исходных данных

Контракт разработки: [docs/SPECIFICATION.md](docs/SPECIFICATION.md), версия **1.6**.
Реализованы обработчик `normalize.py`, восстановление `restore.py`, генератор
тестовых данных и два экспериментальных стенда.
Исходники задания — files/task.txt, files/task.pdf; файла zayavki.xlsx в проекте нет.

Результат — один XLSX с пятью листами **Данные, Проблемы, Оригинал, Аудит, Проверить**.
Телефоны проверяются по структуре; диапазоны операторов и сторонние сайты не используются.
Начальные `00`/`810` всегда считаются неподдерживаемыми префиксами, даже при подходящей длине.
При дублях остаётся первая физическая строка без объединения полей. Разные имена или даты
помечают всю группу как проблемную; различие только источника сохраняется в аудите.
Если первая запись проблемная, группа не получает чистую запись вместо неё.
Исходные записи, значения и байты входной книги сохраняются.

## Обработать свой настоящий XLSX

Из корня проекта выполните команду, заменив путь после `--input` на свой существующий файл:

~~~powershell
.\.venv\Scripts\python.exe normalize.py --input "data\мои заявки.xlsx" --output "result\заявки_result.xlsx"
~~~

Если окружение ещё не установлено, сначала выполните команды раздела «Установка».
Во входном листе первая строка содержит **Имя, Телефон, Дата заявки, Источник**;
порядок этих четырёх колонок может отличаться. Дополнительные заполненные колонки
не допускаются. Если несколько листов имеют такую схему, укажите нужный:

~~~powershell
.\.venv\Scripts\python.exe normalize.py --input "data\мои заявки.xlsx" --output "result\заявки_result.xlsx" --sheet "Заявки"
~~~

Каталог результата создаётся автоматически. Выходной файл должен быть новым;
совпадение с исходником и перезапись существующего файла запрещены.

| Лист результата | Что находится внутри |
|---|---|
| Данные | Только проверенные первые записи: подтверждённое личное имя, телефон +7XXXXXXXXXX, существующая дата YYYY-MM-DD; без ошибок, диагностик и конфликтов |
| Проблемы | Все проблемные исходные строки, включая дубли, с причинами и исходными/обработанными значениями |
| Оригинал | Все исходные записи по порядку с типами ячеек и метаданными, включая гиперссылки |
| Аудит | Изменения, извлечение компонентов ФИО, связи дублей, конфликты, контекст и полный исходный XLSX частями Base64 |
| Проверить | Четыре исходных поля, лист/номер строки и краткое «Что не так» на русском; без JSON |

Однозначные значения меняются; нераспознанные остаются исходными в отчётах. Корректные поля
проблемной строки всё равно стандартизируются в «Проблемах». Листы «Проблемы» и «Проверить» создаются и при отсутствии
проблем. Формулы и ошибки Excel сохраняются безопасным текстом, без вычисления.
Имя с латинскими буквами остаётся для проверки. Наличие проблем не означает ошибку запуска.
«Не знаю» в телефоне, `хх.09.2026`, пропуски обязательных полей и спорные имена не
попадают в «Данные». Пустой источник допустим. Исходные строки полностью сохраняются.

Личное имя: `Влад` → `Влад`; `Зайцев Кирилл` и `Кирилл Зайцев` → `Кирилл`.
Компоненты должны быть подтверждены локальными справочниками и согласованными исключениями.
`К. Белоусов`, неизвестные компоненты и неоднозначные Ким/Али/Ли направляются на проверку.
Полный ФИО остаётся в «Оригинале» и аудите; при дублях разные фамилии не скрываются за
одинаковым извлечённым именем. Отсутствие в словаре не доказывает недействительность имени.
`Иван Иванов Петрович` → `Иван` с NAME_AMBIGUOUS: подтверждённое имя видно в
«Проблемах», вся исходная запись — в «Проверить»/«Оригинале», остальные компоненты
остаются на проверку. Такая заявка не допускается в «Данные».

Даты: `09/03/2026` → `2026-03-09` по приоритету день/месяц. Если этот порядок невозможен,
но месяц/день даёт существующую дату, используется однозначный запасной порядок:
`09/25/2026` → `2026-09-25`, с записью в аудит. Год-месяц-день не переставляется.
Согласованы также даты с пробельными разделителями: `09 03 2026` → `2026-03-09`;
обычные, неразрывные и узкие неразрывные пробелы поддерживаются. Символы внутри
цифровой записи телефона не удаляются по догадке. Эмодзи/пунктуация вокруг целого
номера — дополнительный контекст с пометкой; marks и variation selectors у цифр — ошибка.
Excel serial с форматом только месяца/года/времени остаётся проблемным. Числовые
NaN/Infinity сохраняются как исходные лексемы с CELL_NUMERIC_INVALID; остальные строки
обрабатываются. Ошибки CRC/ZIP/XML по-прежнему приводят к контролируемому отказу.

Перед публикацией программа проверяет пятилистовую структуру, инвентаризацию
строк, дубли, аудит изменений и побайтное восстановление исходника. В консоли выводятся
путь результата, версия правил, количество исходных/итоговых строк, дублей и проблем.

Чтобы извлечь точную исходную книгу из результата:

~~~powershell
.\.venv\Scripts\python.exe restore.py --input "result\заявки_result.xlsx" --output "restored\мои заявки.xlsx"
~~~

Восстановление проверяет индексы частей, Base64, размер и SHA-256. Восстановленный файл
совпадает с входной книгой побайтно; его выходной путь тоже должен быть новым.
Исторические четырёхлистовые результаты версии 1.0–1.3 также поддерживаются.

Коды завершения: **0** — создан результат, **2** — неверный XLSX/схема/лист/объединённые
ячейки, **3** — ошибка чтения/записи или существующий выход, **4** — нарушена проверка
сохранности либо внутренняя ошибка, **5** — превышен предел ресурса/Excel.
При техническом отказе итоговый файл не публикуется.

Лимиты по умолчанию: вход 100 MiB, распакованные ZIP-части 512 MiB, до 1 048 575
исходных строк; параметры `--max-input-bytes`, `--max-uncompressed-bytes`, `--max-rows`
позволяют настроить их. Пределы строк и длины ячейки Excel остаются обязательными.

## Установка

Команды ниже выполняются из корня проекта в PowerShell. Проверенная среда:
Windows, Python **3.14.5**, openpyxl **3.1.5**. Активация виртуального окружения не требуется.

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

Для обработки, восстановления и генератора достаточно корневого requirements.txt.
Для текущих тестов дополнительно нужен research/local-qa-requirements.txt.
Для двух исследовательских стендов дополнительно выполните:

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r research/requirements.txt
~~~

Исследовательские
зависимости нужны обоим стендам: dateparser, phonenumbers, Hypothesis и закреплённые
транзитивные зависимости. После установки проверки работают локально. phonenumbers
используется для сравнения поведения библиотеки, не для принятия бизнес-решений.

Рабочий CLI использует включённый [локальный справочник](normalizer/data/README.md),
не требует DuckDB и ничего не скачивает. Атрибуция данных:
[НЭН — сервис «Имена»](https://n-e-n.ru/imena/), CC BY 4.0;
[russiannames](https://github.com/datacoon/russiannames), BSD-3-Clause.
Исследование и ограничения: [NAME_RESEARCH_REPORT.md](research/NAME_RESEARCH_REPORT.md).

## Генерация корректных и грязных данных

Каждый --output-dir должен быть **новым**. Для повторного запуска используйте другое
имя каталога. Существующие результаты и исходники не перезаписываются.

~~~powershell
.\.venv\Scripts\python.exe tools/generate_data.py --output-dir generated/my-suite --mode suite
.\.venv\Scripts\python.exe tools/generate_data.py --output-dir generated/my-clean --mode clean --rows 1000 --seed 42
.\.venv\Scripts\python.exe tools/generate_data.py --output-dir generated/my-dirty --mode dirty --rows 216
.\.venv\Scripts\python.exe tools/generate_data.py --output-dir generated/my-mixed --mode mixed --rows 48
.\.venv\Scripts\python.exe tools/generate_data.py --output-dir generated/my-1904 --mode dirty --rows 216 --epoch 1904
~~~

suite создаёт **14 XLSX**: clean, dirty, mixed, duplicates, две системы дат,
отсутствующие/повторяющиеся/лишние заголовки, объединённые ячейки, несколько листов,
только заголовки, пустая книга, повреждённый файл. Полный каталог — **216 сценариев**.
Режим dirty содержит и исправимые значения, и ошибки; при меньшем количестве строк
он не покрывает весь каталог. --rows допускает 0…100 000, default — 48.

manifest.json содержит SHA-256 файлов, исходные строки и ожидаемые значения/причины;
cases.json — снимок каталога. Для отдельной книги приоритет имеют её labels в manifest,
в частности при epoch 1904. Ожидание отдельного поля не является полным ожиданием
результата дедупликации строки. Seed воспроизводит значения и метки, не ZIP timestamps.

## Запуск проверок

Основной набор 1.6, включая проверку stateful seed, требует локальные QA-зависимости:

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r research/local-qa-requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe research/run_experiments.py --output-dir generated/my-research
.\.venv\Scripts\python.exe experiments/run_checks.py --output-dir generated/my-gaps --scale-rows 1000
~~~

Первый стенд проверяет исходный Deep Research: телефоны, даты, имена, Excel-типы,
две системы дат, сохранение байтов и свойства на примерах Hypothesis. Источник:
[deep-research-report.md](research/deep-research-report.md); разбор:
[EXPERIMENT_REPORT.md](research/EXPERIMENT_REPORT.md).

Второй стенд проверяет [gap-research.md](experiments/gap-research.md) и приложенное
[дополнительное исследование](experiments/additional-research.md): реальные изменения
ZIP/XML, недостоверный dimension, CRC, дубли ZIP-частей, гиперссылки, bool, ошибки,
формулы, rich text, отказ записи, аварийное завершение и гонку двух генераторов.
План зафиксирован в [PLAN.md](experiments/PLAN.md), выводы — в [REPORT.md](experiments/REPORT.md).

Для проверки на 100 000 строк выполните отдельный запуск:

~~~powershell
.\.venv\Scripts\python.exe experiments/run_checks.py --output-dir generated/my-gaps-large --scale-rows 100000
~~~

Стенды возвращают код 0 при выполненных контрольных ожиданиях, 1 при их нарушении.
Результаты — results.json; дополнительные наблюдения — observations.md у первого
стенда, gap_coverage.json у второго. artifacts.json второго содержит хеши XLSX,
включая намеренно повреждённые фикстуры. Отсутствие ошибок в summary не означает,
что каждое предложение Research принято или проверен готовый обработчик.

После новых запусков проверьте хеши, покрытие каталога и соответствие текущей спецификации:

~~~powershell
.\.venv\Scripts\python.exe tools/verify_artifacts.py --suite generated/my-suite --experiment generated/my-research --experiment generated/my-gaps
~~~

Проверка читает файлы и возвращает 1 при несовпадении хешей, неполном suite, проваленной
проверке стенда или другой версии спецификации. После изменения правил результаты
нужно создать заново в новом каталоге. Для обновления таблицы сценариев в спецификации:

~~~powershell
.\.venv\Scripts\python.exe tools/render_catalog.py
~~~

## Независимая проверка модели, версия 1.6

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r research/local-qa-requirements.txt

.\.venv\Scripts\python.exe -X utf8 tools/run_formal_qa.py --symbolic --seed 20261008 --examples 300 --output-dir generated/my-formal-symbolic-1.6
~~~

Все каталоги результатов должны быть новыми. Стенды работают локально. `all` запускает
основной и генеративный наборы, включая adversarial; фактические ID, исходы тестов и
статистика генераций записываются в JSON. Пустой набор, пропуск, повтор теста и timeout
считаются провалом. Coverage включает Python subprocess и CLI; это не MC/DC всей программы.
Формальный стенд отдельно сохраняет полный перебор, stateful-трассу, независимый ZIP/XML-
инвентарь, результаты настоящего CLI, мутации и хеши. Код завершения 0 означает успех
обязательных проверок; 1 — провал. Без `--symbolic` дополнительный шаг явно NOT_REQUESTED.

Приёмка 1.6: **54 основных + 13 генеративных тестов**, 216 полевых эталонов,
**112945 последовательностей** конечной модели, **112944 условия** ресурсного корпуса;
7 книг/139 исходных строк независимо восстановлены. Все 11 целевых мутаций обнаружены,
все 6 повреждений стадии блокируются до публикации. Контрпримеров в конечной модели нет.
Пример пятилистового результата:
[dirty_result.xlsx](generated/normalizer-1.6-final/dirty_result.xlsx) — 216 исходных,
55 проверенных, 161 проблемная запись, 29 дублей; исходник восстановлен побайтно.

Эти проверки доказывают согласие на указанной области и сохранность конкретных файлов.
Они не доказывают распознавание всех человеческих имён или корректность любого будущего XLSX.
Локальные свидетельства: `generated/qa-1.6-final/`, `generated/formal-1.6-release/`,
`generated/resource-qa-1.6-release/`. В Git сохраняется
[снимок доказательств](docs/FORMAL_VERIFICATION_EVIDENCE.json); `generated/` остаётся локальным.

## Ресурсные проверки и историческая приёмка версии 1.5

Рабочая цепочка: снимок XLSX → проверка ZIP/XML и типов ячеек → независимые анализаторы
имени/телефона/даты → первый представитель телефона → пять листов → проверка инвентаризации
и побайтного восстановления → публикация нового файла. Рабочие зависимости — только
openpyxl и et-xmlfile плюс включённый справочник имён. Сеть при обработке не используется.

Для текущего локального QA достаточно отдельного минимального набора; DuckDB,
dateparser и phonenumbers для этих команд не нужны:

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r research/local-qa-requirements.txt
.\.venv\Scripts\python.exe tools/run_qa.py --mode all --seed 20261008 --examples 1000 --output-dir generated/my-qa-1.5
.\.venv\Scripts\python.exe tools/fetch_qa_resources.py --output-dir generated/my-resource-sources
.\.venv\Scripts\python.exe research/run_resource_qa.py --sources generated/my-resource-sources --output-dir generated/my-resource-qa --seed 20261008 --examples 300
.\.venv\Scripts\python.exe tools/verify_artifacts.py --resource-qa generated/my-resource-qa
~~~

Только `fetch_qa_resources.py` обращается к сети: загружает закреплённые Unicode 16.0.0,
CLDR 47 и метаданные libphonenumber 9.0.41 с лицензиями, проверяет размер и SHA-256
по [lock-файлу](research/resource_sources.lock.json). Повторные проверки работают полностью
локально; отсутствующий/изменённый кеш вызывает отказ без автоматической загрузки.
Все выходные каталоги должны быть новыми. Unicode-корпус сверяется с Python UCD 16.0.0,
проверенным в Python 3.14.5; другую версию стенд явно отклоняет.

Источники расширяют тестовые входы, а ожидания задаёт спецификация. Стенд проверяет
Unicode-цифры, marks/невидимые символы, NFC, визуальные двойники, календарные границы,
RU/KZ и телефонные группировки, комбинации Hypothesis и пары факторов настоящего CLI.
Проверяются shared/inline/rich text, кодировки, неверный dimension, повреждённые XML,
отсутствующие части и лимиты; отдельно — пять листов, исходные значения и все байты.
План и результаты итераций: [RESOURCE_QA_PLAN.md](docs/RESOURCE_QA_PLAN.md),
[RESOURCE_QA_REPORT.md](docs/RESOURCE_QA_REPORT.md).

Финальная проверка 1.5: **44 основных + 13 расширенных тестов**, 215 эталонных сценариев,
**112 944 условия ресурсного стенда**, 28 запусков CLI; ошибок проверок нет.
Сохранность всех исходных строк и байтов проверена у 17 успешно созданных книг.
Пример результата: [dirty_result.xlsx](generated/normalizer-1.5-final/dirty_result.xlsx).

## Исторические массовые проверки, версия 1.4

План до изменений: [QA_PLAN.md](docs/QA_PLAN.md); дефекты и фактические результаты:
[QA_REPORT.md](docs/QA_REPORT.md). Базовые тесты этой исторической версии не требовали исследовательских зависимостей;
для текущего набора 1.6 требуется research/local-qa-requirements.txt.
Для расширенного QA:

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r research/qa-requirements.txt
.\.venv\Scripts\python.exe tools/run_qa.py --mode smoke --output-dir generated/my-smoke
.\.venv\Scripts\python.exe tools/run_qa.py --mode p0 --output-dir generated/my-p0
.\.venv\Scripts\python.exe tools/run_qa.py --mode generated --seed 7 --examples 1000 --output-dir generated/my-generated
.\.venv\Scripts\python.exe tools/run_qa.py --mode adversarial --output-dir generated/my-adversarial
.\.venv\Scripts\python.exe tools/check_mutations.py --output-dir generated/my-mutations
~~~

`--mode all` объединяет основные и генеративные проверки. Каждый каталог должен быть новым.
Сохраняются реальные логи, результаты, счётчики и покрытие. `--examples` — верхний предел,
конечные стратегии исчерпываются раньше; Hypothesis сохраняет базу в `.hypothesis/`.
Код 1 означает провал проверки. Готовые новые пятилистовые результаты:

## Границы подтверждённого результата

Пятилистовая обработка и восстановление через CLI реализованы и проверены.
Исторические исследовательские отчёты описывают отдельные модели; приёмочные тесты
обработчика находятся в tests/test_normalizer.py и tests/test_formal.py. Зашифрованные книги, XLS/XLSM,
DTD/ENTITY и повреждённые контейнеры отклоняются. Проверенная платформа — Windows;
гонка публикации на POSIX не испытана. Исторический массовый замер относится к генерации
и чтению фикстуры; отдельный новый замер 99,789 с относится к полному обработчику.
Файл заказчика в проект не предоставлен; готовые результаты выше получены из тестовых книг.
Девять целевых ручных мутаций обнаружены; это не полный анализ mutation coverage.
